# Working with Panels

## Existing Panels

Karagöz Sandbox provides 4 panels:
1. Code: renders the file explorer (if not hidden) and the currently open editors.
2. Result: renders the preview frame and the address bar (if enabled).
3. Processes: renders currently running and finished processes.
4. Terminals: renders the open shell terminals (`jsh` &mdash; a custom shell that comes out of the box with 
   WebContainer API).

These 4 panels fall into 2 groups, each with its own visibility rule:
* **Main panels** (Code, Result): at least one must always be shown. They can also be shown side by side.
* **Drawer panels** (Processes, Terminal): mutually exclusive &mdash; showing one hides the other &mdash; and both
  may be hidden at the same time.

The panels are controlled through 2 models of `KrgzSandbox`:
* `availablePanels`: controls which panels are available to the user, which in turn means which toggles to show to 
  the user so they can show and hide panels. 
  <br>
  Default: `['code', 'processes', 'result', 'terminal']` (all panels are available).
* `shownPanels`: controls which panels to show initially.
  <br>
  Default: `['code', 'result']`.

```html
<!-- show toggles for all panels and show all panels initially -->
<KrgzSandbox
        :available-panels="['code', 'processes', 'result', 'terminal']"
        :shown-panels="['code', 'processes', 'result']"
/>

<!-- show toggles for "code" and "result" and show only the "result" panel initially -->
<KrgzSandbox
        :available-panels="['code', 'result']"
        :shown-panels="['result']"
/>
```

::hint
Since Code/Result and Processes/Terminal follow different visibility rules, an initial `shownPanels` value can be
conflicting. Karagöz Sandbox resolves this once, when the sandbox is first set up:
* If `shownPanels` includes **both** drawer panels (`processes` and `terminal`), only the one that appears
  **last** in the array is kept.
* If, after that, `shownPanels` includes **neither** main panel (`code` nor `result`), `code` is added so a main
  panel is always visible.

This resolution only runs once for the initial value &mdash; toggling panels afterwards always respects the
exclusivity rules above.
::

## Layout

### Desktop

On wide enough containers (see [`multiPanelFrom`](/sandbox/handbook/props-and-events#multipanelfrom)), `KrgzSandbox`
renders a 4-row layout:
1. **Main toolbar**: toggles for Code and Result, plus the Solve, fullscreen and theme action buttons (each can be
   hidden individually, see [Props](/sandbox/handbook/props-and-events)).
2. **Main panels**: the Code and/or Result panel content, resizable and shown side by side when both are visible.
3. **Drawer toolbar**: toggles for Processes and Terminal, plus a close/open icon that collapses or reopens the
   whole drawer. This row (and row 4) is only rendered when at least one drawer panel is available.
4. **Drawer**: the Processes or Terminal panel content, only rendered while a drawer panel is shown.

### Mobile

Below the configured width (or when `multiPanelFrom="none"`), `KrgzSandbox` switches to a single-panel, mobile-first
layout instead of just shrinking the 4-row layout:
* A minimal top bar with an overflow menu holding the Solve, theme and fullscreen actions.
* The content area, showing exactly one panel at a time.
* A bottom tab bar with one toggle per available panel (Code, Result, Processes, Terminal). Tapping a tab makes
  that panel the one shown, regardless of whether it's normally a "main" or "drawer" panel on desktop &mdash; on
  mobile there is no main/drawer distinction, only a single active panel.

::hint
`shownPanels` can still list more than one panel while in mobile layout (e.g. as configured for desktop); only the
first entry is used to decide which panel is initially shown. Tapping a bottom-bar tab moves that panel to the
front of the list.
::

## Panel Components

`KrgzSandbox` renders the panel contents in slots as follows:

| Slot        | Component                              | Role                                    |
|-------------|----------------------------------------|-----------------------------------------|
| `explorer`  | `<KrgzExplorer />`                     | The file explorer in the code panel.    |
| `editor`    | `<KrgzEditorTabs />`                   | The open editors in the code panel.     |
| `preview`   | `<KrgzPreview />`                      | The preview frame with the address bar. |
| `processes` | `<KrgzProcessTabs mode="process" />`   | Running and finished processes.         |
| `terminal`  | `<KrgzProcessTabs mode="terminal" />`  | Open terminals.                         |

These components get all they need to operate by calling `useKaragozSandbox()`, which is why they take no props (with 
the exception of the `mode` prop of `KrgzProcessTabs`).

This gives more flexibility, allowing the following scenarios:

### Replacing Panels

You can replace any or all of the panel components and still use the structure provided by `KrgzSandbox`, 
retaining its functionality (toggles, resizable panels, additional function buttons).

```html
<KrgzSandbox>
  <template #explorer>
    <MyExplorer />
  </template>
  <template #editor>
    <MyEditor />
  </template>
  <template #preview>
    <MyPreview />
  </template>
  <template #processes>
    <MyProcesses />
  </template>
  <template #terminal>
    <MyTerminal />
  </template>
</krgzSandbox>
```

For a practical example let's replace the default explorer with a simple list to edit an HTML file, a JavaScript 
file and CSS file.

```vue
<script setup lang="ts">
const { boot, isBooting } = useSandboxBoot()
provideWebContainer(boot)

const sandbox = useSandbox()

// ... omitted for readability 
</script>

<template>
  <KrgzSandbox :booting="isBooting" hide-solve-button>
    <template #explorer>
      <div class="p-1 text-sm">
        Your files:
        <ul class="list-disc list-inside">
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/index.html')">HTML</a>
          </li>
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/script.js')">JS</a>
          </li>
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/style.css')">CSS</a>
          </li>
        </ul>
      </div>
    </template>
  </KrgzSandbox>
</template>
```

### Replacing KrgzSandbox Itself

You can also utilise the provided panel components without sticking to the default layout and functionality provided 
by  `KrgzSandbox`.

The following example renders the editor and the result in a simple `div` element without using `KrgzSandbox`.

```vue
<template>
  <div class="grid grid-cols-2 h-full">
    <div class="border-r">
      <KrgzEditorTabs v-if="!isBooting" />
    </div>
    <div>
      <KrgzPreview v-if="!isBooting" />
    </div>
  </div>
</template>
```
