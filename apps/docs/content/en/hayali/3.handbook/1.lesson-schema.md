# Lesson Schema

A lesson is plain data. That is on purpose: you can keep it in a file, generate it, translate it and validate it
without a browser.

| Concept | Type | What it is |
| ------- | ---- | ---------- |
| Lesson | [`Lesson`](/hayali/api-reference/interfaces/Lesson) | The whole thing: base files plus chapters. |
| Chapter | [`Chapter`](/hayali/api-reference/interfaces/Chapter) | A titled group of steps. |
| Step | [`Step`](/hayali/api-reference/interfaces/Step) | One screen of explanation and the sandbox state it is about. |
| Position | [`Position`](/hayali/api-reference/interfaces/Position) | `{ chapterId, stepId }`: where the learner is. |

## Ids

Chapters and steps have an `id` that **you** choose. Step ids are unique within their chapter, chapter ids within the
lesson. Ids are never derived from titles. Use them to save and restore a position, or to key translations.

## What a step can carry

* `title` and `body` (markdown, with [callouts](/hayali/handbook/callouts)).
* `adjustments` and `removals`: [which files the step changes](/hayali/handbook/adjustments-and-removals).
* `locks`: [which files are read-only for the step](/hayali/handbook/locks).
* `editor` and `preview`: [where to direct the learner's attention](/hayali/handbook/editor-directives).

Everything except `id`, `title` and `body` is optional. A lesson written for an earlier version, without `editor` or
`preview`, keeps working unchanged.

## Validate

[`validateLesson()`](/hayali/api-reference/functions/validateLesson) checks a lesson against each step's resolved file
tree and returns a list of [`LessonIssue`](/hayali/api-reference/interfaces/LessonIssue)s. An empty list means the
lesson is valid. It never throws, even for malformed input, so you can run it on lessons loaded from JSON.

```typescript
const issues = validateLesson(lesson)
// e.g. { rule: 'missing-file', chapterId: 'intro', stepId: 'shout', path: 'app.js', message: '…' }
```
