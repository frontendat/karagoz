# Editor Directives

A step cannot only change files, it can also direct the learner's attention. The optional `editor` block and the
optional `preview` describe what the editor and the preview should show **every time the step is entered**: coming
forward, going back, or loading the lesson on that step.

```typescript
{
  id: 'behaviour',
  title: 'Behaviour',
  body: '…',
  editor: {
    close: ['style.css'],
    open: ['index.html', { path: 'app.js', line: 6 }],
    highlight: [{ path: 'app.js', lines: [[6, 9]] }],
  },
  preview: { url: '/about.html' },
}
```

The shapes are documented in [`EditorDirective`](/hayali/api-reference/interfaces/EditorDirective) and
[`LineSpec`](/hayali/api-reference/type-aliases/LineSpec).

## No inheritance

Directives are derived from the step alone. A step without `editor` has no directives; it does not repeat the previous
step's. Hayali does not move DOM focus, and tabs the learner opened themselves stay open unless the step closes them.

## open

A list of paths, optionally `{ path, line }`. Files open in order, so the **last** one is active. If the last entry
has a `line`, the editor scrolls there and puts the cursor on it.

## close

A list of paths, or `'all'`. Closing runs before opening, so `{ close: 'all', open: ['index.html'] }` leaves exactly
one tab. A removed file's tab is always closed automatically.

## highlight

A list of `{ path, lines }`. `lines` is a **line spec**; lines are 1-based and inclusive:

| Line spec | Highlights |
| --------- | ---------- |
| `3` | Line 3 |
| `[3, 7]` | Lines 3 to 7 |
| `[2, [5, 7], 9]` | Lines 2, 5 to 7 and 9 |

Highlighting never opens or focuses a file. If the file is not open, the highlight shows once it is opened. All
highlights are cleared when the learner leaves the step and on their first edit, so they never point at shifted lines.

## preview.url

`preview.url` makes the preview show a page. It is **root-relative** (starts with a single `/`) and may carry a query
and a hash, for example `/about.html?lang=en#top`; it never contains the WebContainer's origin.

* On the first step shown, the URL waits until the dev server is ready.
* Without `preview.url`, the preview stays on its page and is **reloaded**, so it shows the files of the new step. The
  exception: after a step removed files and the preview is not on `/`, it goes back to `/` instead. An explicit
  `preview.url` always wins over that fallback (and if the preview is already on that page, it is reloaded).

## When a directive is wrong

A directive that points outside the step's file tree is skipped with a console warning in development; it never throws
or breaks the lesson. Use [`validateLesson()`](/hayali/api-reference/functions/validateLesson) to catch these mistakes
before your learners do.

## On small screens

When the Sandbox panel is hidden behind the Lesson/Sandbox toggle, `open`, `close`, `highlight` and `preview` are applied
right away. Jumping to a line waits until the Sandbox panel is visible. Hayali never switches the panel for the learner.
