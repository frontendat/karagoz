# Adjustments and Removals

A lesson has a **base tree** (`Lesson.files`). Each step describes the file tree it wants as a small change on top of
that base:

```
step tree = base files + the step's adjustments − the step's removals
```

* **Adjustments** (`Step.adjustments`) add or change files. They use the same nested shape as the base tree.
* **Removals** (`Step.removals`) are paths that are deleted when the step is entered.

## Steps are not cumulative

A step's tree is built from the base and **only its own** adjustments. It does not inherit the previous step's
adjustments. If step 3 should still contain the CSS written in step 2, step 3 lists it again:

```typescript
const styled = { 'style.css': file('body { margin: 0 }') }

steps: [
  { id: 'style', title: 'Style', body: '…', adjustments: styled },
  { id: 'behave', title: 'Behave', body: '…', adjustments: { ...styled, 'app.js': file('…') } },
]
```

This is what makes every step reproducible: moving back and forth always lands in the same state.

## What happens when you move

On entering a step, Hayali removes the files of the old step that are not in the new tree, then writes the new tree.
That is why a file added by one step simply vanishes in the next one. Listing it under `removals` is allowed and makes
the intent explicit (the demo does so with `about.html`); `removals` is what deletes files that are in the **base**.

When a file disappears this way, its editor tab closes by itself, and if the preview was left on a page that no
longer exists, it goes back to `/` (unless the step has its own [`preview.url`](/hayali/handbook/editor-directives)).

## Immutable files

Some files should never be touched, for example `package.json` and the server script. List them in
`Lesson.immutable` (gitignore-style patterns). Immutable files are mounted once at boot and are neither tracked for
edits nor reset. Everything else is a **resettable** file.

`node_modules` and the lockfiles package managers write (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`)
are always immutable, whether you list them or not. Installing dependencies after boot therefore never counts as an edit,
and a reset never deletes them.

::hint
Immutable is not the same as [locked](/hayali/handbook/locks). Immutability is about resetting; a lock only makes a
file read-only in the UI for one step.
::
