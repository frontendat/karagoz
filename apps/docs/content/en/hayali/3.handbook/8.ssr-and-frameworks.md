# SSR and Frameworks

Karagöz Hayali renders on the server. The lesson is meant to be readable without JavaScript, and by search engines.

## What the server renders

* Every step body of the current chapter, in the HTML. Steps that are not current are collapsed in the UI but still
  present.
* The layout, chosen by CSS (see [Layout](/hayali/handbook/layout)).
* A placeholder instead of the sandbox. The WebContainer only exists in the browser and boots on mount.
* The step from `position`, or the first step of the first chapter if you pass none. Hayali never restores a position
  from `localStorage`.

## What you provide

* **COOP/COEP headers** on the page, so the browser can run WebContainers. In development, Hayali logs one warning if
  the page is not cross-origin isolated.
* **The stylesheets** of `@karagoz/shared`, `@karagoz/sandbox` and `@karagoz/hayali` in the server-rendered output.
* **A fresh `vue-i18n` per app (and per request on the server)** with `i18nMessages` merged, and the locale taken from
  a prop or your framework.
* **`provideWebContainer(useSandboxBoot().boot)`** in a component above `KrgzHayali`. Booting is mount-only, so this
  is safe to call while rendering on the server.

## Nuxt

This is the setup used by this very site, verified through the demo on the [Getting Started](/hayali/getting-started)
page.

```typescript
/* nuxt.config.ts */
export default defineNuxtConfig({
  css: ['~/assets/css/karagoz.css'],            // imports the three @karagoz/* stylesheets
  routeRules: {
    '/*': {
      headers: {
        'Cross-Origin-Embedder-Policy': 'require-corp',
        'Cross-Origin-Opener-Policy': 'same-origin',
      },
    },
  },
  modules: ['@nuxtjs/i18n'],
})
```

```typescript
/* i18n/locales/en.ts: merge the single pack */
export default defineI18nLocale(async () => ({
  ...(await import('@karagoz/hayali')).i18nMessages.en,
  /* your own messages */
}))
```

Wrap the lesson in a component that provides the WebContainer, take the locale from `useI18n()`, and render it as a lazy
component with `hydrate-on-visible`. The lesson text stays in the server HTML, and the WebContainer boots only once the
lesson is scrolled into view:

```vue
<template>
  <LazyMyLessonRunner hydrate-on-visible :locale="locale" />
</template>
```

No `<ClientOnly>` is needed.

## Astro

::hint{variant='destructive'}
This recipe has not been verified yet. It is the supported path based on how Hayali works, but it is untested.
::

* Render the lesson from **a single Vue island** that contains `KrgzHayali` and provides the WebContainer.
* Create a **fresh `vue-i18n` instance per island** through the Vue integration's `appEntrypoint`, and merge
  `i18nMessages` into it.
* Hydrate with `client:visible`, so the WebContainer boots when the island scrolls into view.
* Serve the COOP/COEP headers from your host or adapter, and include the three stylesheets in the page.

```typescript
/* src/pages/_app.ts, registered with vue({ appEntrypoint: '/src/pages/_app' }) */
import type { App } from 'vue'
import { createI18n } from 'vue-i18n'
import { i18nMessages } from '@karagoz/hayali'

export default (app: App) => {
  app.use(createI18n({ legacy: false, locale: 'en', fallbackLocale: 'en', messages: i18nMessages }))
}
```
