# Setup

Setting up Karagöz Hayali takes four steps: install, serve with the right headers, import the styles and merge the
translations.

## Installation

Install the following packages using your preferred package manager. Hayali builds on Karagöz Sandbox, and needs
`vue` and `vue-i18n` as peer dependencies.

```shell
# NPM
npm install --save @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# PNPM
pnpm add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Yarn
yarn add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Bun
bun add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n
```

## Cross-Origin Isolation

The sandbox runs on WebContainers, which require the page to be cross-origin isolated. Serve it with:

```
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Opener-Policy: same-origin
```

`require-corp` also constrains cross-origin assets (images, fonts, scripts) on the page: they need a matching
`Cross-Origin-Resource-Policy` header or CORS. In development Hayali logs a single warning when the page is not
cross-origin isolated. See [Setup of Karagöz Sandbox](/sandbox/setup) for the Vite and Nuxt configuration.

## Styles

Import the styles of all three packages, for example in your main stylesheet:

```css
/* main.css */
@import "@karagoz/shared/dist/karagoz-shared.css";
@import "@karagoz/sandbox/dist/karagoz-sandbox.css";
@import "@karagoz/hayali/dist/karagoz-hayali.css";
```

If you render on the server, make sure these stylesheets are part of the server-rendered output. The first paint of
the layout is decided by CSS alone, so a missing stylesheet shows up as an unstyled lesson.

## I18N

Hayali uses `vue-i18n`. `i18nMessages` is a complete language pack for English, German and Arabic that **already
includes the sandbox messages**, so you merge a single object. All keys live under one `krgz` root
(`krgz.dir`, `krgz.sandbox.*`, `krgz.hayali.*`).

```typescript
/* i18n.ts */
import { createI18n } from 'vue-i18n'
import { i18nMessages } from '@karagoz/hayali'

export const createAppI18n = (locale: string) =>
  createI18n({
    locale,
    fallbackLocale: 'en',
    messages: {
      ar: { ...i18nMessages.ar },
      de: { ...i18nMessages.de },
      en: { ...i18nMessages.en },
    },
  })
```

## Providing the WebContainer

The sandbox gets its WebContainer through `provideWebContainer()`. `useSandboxBoot()` boots it on mount only, which
makes it safe to call while rendering on the server:

```vue
<script setup lang="ts">
import { KrgzHayali, type Lesson } from '@karagoz/hayali'
import { provideWebContainer, useSandboxBoot } from '@karagoz/sandbox'
import { onBeforeUnmount, ref } from 'vue'

defineProps<{ lesson: Lesson }>()
const position = ref({ chapterId: 'intro', stepId: 'welcome' })

const { boot } = useSandboxBoot()
provideWebContainer(boot)
onBeforeUnmount(() => void boot.then((container) => container.teardown()))
</script>

<template>
  <KrgzHayali :lesson="lesson" v-model:position="position" />
</template>
```

Only one WebContainer can run at a time. Tear it down when the component goes away, as above; otherwise coming
back to the page boots a second one and the browser reports *Only a single WebContainer instance can be booted*.

## Consumer responsibilities

Hayali deliberately leaves these to your app:

* **Headers.** Serve COOP/COEP as described above.
* **Styles in SSR output.** Include the `@karagoz/*` stylesheets in server-rendered pages.
* **A fresh `vue-i18n` per app or request.** Create the i18n instance per request on the server, merge
  `i18nMessages` and take the locale from a prop or your framework. Hayali never reads `localStorage`.
* **The position.** Pass `position` (a `{ chapterId, stepId }` pair) with `v-model:position`. If you omit it, the
  first step of the first chapter is used. Persisting the position (URL, storage) is up to you.
