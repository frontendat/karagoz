# التعديلات والحذف

للدرس (Lesson) **شجرة أساسية** (`Lesson.files`). وتصف كل خطوة (Step) شجرة الملفات التي تريدها على هيئة تغيير صغير فوق تلك الأساسية:

```
شجرة الخطوة = الملفات الأساسية + تعديلات الخطوة − عمليات الحذف في الخطوة
```

* **التعديلات** (Adjustments، أي `Step.adjustments`) تضيف ملفات أو تغيّرها. وتأخذ الشكل المتداخل نفسه للشجرة الأساسية.
* **عمليات الحذف** (Removals، أي `Step.removals`) هي مسارات تُحذف عند دخول الخطوة.

## الخطوات ليست تراكمية

تُبنى شجرة الخطوة من الشجرة الأساسية و**تعديلاتها هي فقط**. فلا ترث تعديلات الخطوة السابقة. وإذا كان يجب أن تحتفظ الخطوة 3
بـ CSS المكتوب في الخطوة 2، فعليها أن تذكره من جديد:

```typescript
const styled = { 'style.css': file('body { margin: 0 }') }

steps: [
  { id: 'style', title: 'Style', body: '…', adjustments: styled },
  { id: 'behave', title: 'Behave', body: '…', adjustments: { ...styled, 'app.js': file('…') } },
]
```

وهذا ما يجعل كل خطوة قابلة لإعادة الإنتاج: فالتنقّل ذهابًا وإيابًا ينتهي دائمًا إلى الحالة نفسها.

## ما يحدث عند الانتقال

عند دخول خطوة، يحذف Hayali ملفات الخطوة القديمة غير الموجودة في الشجرة الجديدة، ثم يكتب الشجرة الجديدة. ولهذا يختفي ملف
أضافته خطوة ما في الخطوة التالية من تلقاء نفسه. وذكره ضمن `removals` مسموح ويوضّح القصد (يفعل الدرس التوضيحي ذلك مع
`about.html`)؛ أما `removals` فهي ما يحذف الملفات الموجودة في **الشجرة الأساسية**.

وعندما يختفي ملف بهذه الطريقة، يُغلق تبويب المحرر الخاص به تلقائيًا، وإذا بقيت المعاينة على صفحة لم تعد موجودة فإنها تعود إلى
`/` (ما لم يكن للخطوة [`preview.url`](/hayali/handbook/editor-directives) خاص بها).

## الملفات غير القابلة للتغيير

بعض الملفات يجب ألا تُمَسّ أبدًا، مثل `package.json` وسكربت الخادم. أدرجها في `Lesson.immutable` (أنماط بأسلوب gitignore).
تُحمَّل الملفات غير القابلة للتغيير (Immutable) مرة واحدة عند الإقلاع، ولا تُراقَب بحثًا عن تعديلات ولا تُعاد إلى أصلها. وكل ما
عداها ملفات **قابلة لإعادة الضبط**.

::hint
عدم القابلية للتغيير ليس هو [القفل](/hayali/handbook/locks). فالأولى تتعلق بإعادة الضبط، أما القفل فيجعل الملف للقراءة فقط
في الواجهة لخطوة واحدة.
::
