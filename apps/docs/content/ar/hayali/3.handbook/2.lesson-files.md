# ملفات الدروس

لا يلزم كتابة [الدرس](/hayali/handbook/lesson-schema) ككائن. يمكن أن يكون ملف Markdown واحدًا، أي **ملف درس**، تُصرِّفه
الدالة [`parseLesson()`](/hayali/api-reference/functions/parseLesson) إلى `Lesson` نفسه. تكتب النص والشيفرة في كتل (fences)
حقيقية، وتقرأ الدرس من أعلاه إلى أسفله.

تأتي `parseLesson()` من `@karagoz/hayali/parse`. وهي دالة نقية لا تعتمد على Vue ولا على Node، فتعمل في المتصفح أو في سكربت
البناء أو في اختبار. ولا ترمي استثناءً أبدًا: يُعاد ما أمكن بناؤه مع قائمة بالمشكلات (issues).

```typescript
import { parseLesson } from '@karagoz/hayali/parse'

const { lesson, issues } = parseLesson(markdown)
```

يُكتب ملف الدرس بلغة واحدة. والترجمة ملف مستقل بالمعرّفات نفسها.

## شكل الملف

````markdown
```yaml krgz-lesson
immutable:
  - package.json
```

```json file=package.json
{ "name": "tiny-counter", "private": true }
```

```html file=index.html
<button id="button">Click me</button>
```

```js file=app.js
// Behaviour goes here.
```

# The page {#basics}

## Markup {#markup}

Every page starts as HTML. `index.html` is open in the editor.

```yaml krgz-step
editor:
  open: [index.html]
```

## Behaviour {#behaviour}

`app.js` now handles the click.

```js file=app.js
document.getElementById('button').addEventListener('click', () => alert('Hi'))
```

```yaml krgz-step
editor:
  open: [app.js]
```
````

| Markdown | يصبح |
| -------- | ---- |
| `# العنوان {#id}` | فصلًا (Chapter). |
| `## العنوان {#id}` | خطوة (Step) من الفصل الحالي. |
| النص تحت عنوان الخطوة | `body` الخطوة. |
| كتلة فيها `file=<path>` | ملفًا: في الشجرة الأساسية إن جاءت قبل أول فصل، وتعديلًا (Adjustment) إن جاءت داخل خطوة. |
| كتلة `krgz-lesson` | إعدادات على مستوى الدرس، قبل أول فصل. |
| كتلة `krgz-step` | توجيهات الخطوة، داخل الخطوة. |

لا يبني الدرسَ إلا العناوين `#` و`##`. أما العناوين الأعمق فتبقى جزءًا من نص الخطوة.

## المعرّفات

ينتهي كل عنوان فصل وخطوة بـ `{#id}`. ويتكوّن المعرّف من حروف وأرقام و`_` و`-`. معرّفات الفصول فريدة في الدرس، ومعرّفات الخطوات
فريدة داخل فصلها. وكما في [مخطط الدرس](/hayali/handbook/lesson-schema)، لا تُشتق المعرّفات من العناوين أبدًا. والعنوان بلا
معرّف، أو بمعرّف غير صالح أو مكرر، خطأ. وكذلك الفصل الذي لا خطوات فيه.

## كتلة الدرس

تحمل الكتلة الاختيارية `krgz-lesson` إعدادات على مستوى الدرس. وفيها اليوم مفتاح واحد هو `immutable`، وهو قائمة بأنماط
[الملفات غير القابلة للتغيير](/hayali/handbook/adjustments-and-removals). يُسمح بكتلة درس واحدة على الأكثر، وقبل عنوان أول فصل فقط.

````markdown
```yaml krgz-lesson
immutable:
  - package.json
  - server.js
```
````

## كتل الملفات

الكتلة التي يحتوي نص معلوماتها على `file=<path>` ملفٌّ. فإن جاءت قبل أول فصل فهي من **الشجرة الأساسية**، وإن جاءت داخل خطوة
فهي أحد [تعديلات](/hayali/handbook/adjustments-and-removals) الخطوة. يمكن أن يظهر المسار مرة واحدة في كل خطوة ومرة واحدة في
الأساس. وتأخذ الكتلة محتواها من **مصدر واحد** من ثلاثة:

| تُكتب بصيغة | يأتي المحتوى من |
| ----------- | --------------- |
| متن | الكتلة نفسها. |
| `from=<ref>` ومتن فارغ | نسخة الملف نفسه في خطوة أخرى. |
| `src=<path>` ومتن فارغ | ملف بجانب ملف الدرس. |

إعطاء الكتلة متنًا مع `from=` أو `src=`، أو إعطاؤها `from=` و`src=` معًا، خطأ.

### from=

يعيد `from=` استخدام ملف بدل نسخه، وبه تحتفظ الخطوة بما كتبته خطوة سابقة:

````markdown
```css file=style.css from=style
```

```js file=app.js from=basics/behaviour
```
````

المرجع إما معرّف خطوة في الفصل نفسه (`style`)، أو خطوة في أي فصل (`basics/behaviour`)، أو `base` لنسخة الشجرة الأساسية. ويجب أن
تكون للخطوة المشار إليها نسخة خاصة بها من الملف، أو أن تحصل عليها عبر `carry`؛ ولا يُرجع إلى الأساس إلا إذا طلبته. يوسّع المحلّل
المراجع، فلا يحتوي `Lesson` المُصرَّف على أي منها.

### src=

يحمّل `src=` المحتوى من ملف آخر، للشيفرة الأطول من أن تُقرأ داخل الملف. المسار نسبي إلى ملف الدرس ويجب أن يبقى داخل مجلده. والتحليل
نقيّ، لذلك تُمرِّر القارئ عبر الخيار `resolveSrc`؛ وبدونه يكون كل `src=` غير محلول. وتسرد `srcPaths` في النتيجة ما طُلب، وهذا ما تحتاجه
أداة البناء لإبطال ذاكرتها المؤقتة.

```typescript
const { lesson } = parseLesson(markdown, {
  resolveSrc: (path) => files[path],
})
```

## كتلة الخطوة

تحمل الكتلة الاختيارية `krgz-step` توجيهات خطوة واحدة. يُسمح بكتلة واحدة على الأكثر لكل خطوة.

````markdown
```yaml krgz-step
locks: [index.html]
removals: [about.html]
editor:
  close: [style.css]
  open:
    - path: app.js
      line: 6
  highlight:
    - path: style.css
      lines: 1-7, 13-17
preview:
  url: /about.html
```
````

| المفتاح | يقابل | انظر |
| ------- | ----- | ---- |
| `locks` | `Step.locks` | [الأقفال](/hayali/handbook/locks) |
| `removals` | `Step.removals` | [التعديلات والحذف](/hayali/handbook/adjustments-and-removals) |
| `editor` | `Step.editor` | [توجيهات المحرر](/hayali/handbook/editor-directives) |
| `preview` | `Step.preview` | [توجيهات المحرر](/hayali/handbook/editor-directives) |
| `carry` | | الترحيل (Carry) أدناه |

المفاتيح غير المعروفة أخطاء، حتى لا تمرّ الأخطاء المطبعية بصمت. وكذلك الكتل المسمّاة بأي اسم آخر يبدأ بـ `krgz-`.

### مواصفات الأسطر

في `editor.highlight` يقبل `lines` [مواصفة الأسطر](/hayali/api-reference/type-aliases/LineSpec) بصيغة YAML (`7` أو `[3, 7]` أو
`[[1, 7], [13, 17]]`) أو بصيغة نصية مختصرة: `7` أو `3-7` أو `1-7, 13-17`. تبدأ الأسطر من 1 وتشمل الطرفين.

## الترحيل (Carry)

الخطوات ليست تراكمية: تبدأ كل خطوة من الأساس وبتعديلاتها وحدها. ويتيح `carry` أن تبدأ الخطوة من خطوة أخرى بدل ذلك:

````markdown
## Behaviour {#behaviour}

```yaml krgz-step
carry: style
```

```js file=app.js
// Only the new file is written. style.css comes from the "style" step.
```
````

تحصل الخطوة على كل ملفات الخطوة المُرحَّلة، إضافة إلى كتلها الخاصة، وتتغلب كتلها عند تسمية المسار نفسه. والمرجع معرّف خطوة (في الفصل
نفسه) أو `chapter/step`. ويمكن لخطوة مُرحَّلة أن ترحّل خطوة أخرى، وتُتبع السلسلة.

الذي يُرحَّل **التعديلات** فقط. أما الأقفال وتوجيهات المحرر والمعاينة وعمليات الحذف فلا تُورَّث أبدًا، لأنها تصف لحظة الخطوة لا
ملفاتها. وإذا حذفت الخطوة المُرحَّلة ملفًا تعيده هذه الخطوة بالترحيل، فسيظهر تحذير.

## المشكلات (Issues)

تعيد `parseLesson()` كائن [`ParseIssue`](/hayali/api-reference/interfaces/ParseIssue) لكل مشكلة، مع `line` (يبدأ من 1) و`severity`
هي `error` أو `warning`، و[`rule`](/hayali/api-reference/type-aliases/ParseIssueRule) تسمّي ما حدث:

| المجال | القواعد |
| ------ | ------- |
| العناوين والمعرّفات | `missing-id` و`invalid-id` و`duplicate-id` و`step-outside-chapter` و`empty-chapter` |
| الكتل | `unclosed-fence` و`unknown-fence` و`file-outside-step` و`missing-file-path` و`duplicate-file` |
| كتل التوجيهات | `malformed-yaml` و`unknown-key` و`invalid-value` و`misplaced-lesson-block` و`duplicate-lesson-block` و`misplaced-step-block` و`duplicate-step-block` |
| مصادر الملفات | `conflicting-file-source` و`ref-with-body` و`src-with-body` و`invalid-src` و`unresolved-src` |
| المراجع | `ref-unknown-step` و`ref-missing-path` و`ref-cycle` |
| الترحيل | `carry-unknown-step` و`carry-cycle` و`carry-drops-removals` (التحذير الوحيد) |
| أخرى | `parser-failure` |

تشير الأخطاء داخل كتلة `krgz-lesson` أو `krgz-step` إلى المفتاح بالضبط. والـ`lesson` في النتيجة مبنيّ بأفضل جهد، فيبقى موجودًا مع
الأخطاء؛ أصلحها قبل الاعتماد عليه.

### التحليل والتحقق

يفحص التحليل صياغة الملف. وتفحص [`validateLesson()`](/hayali/api-reference/functions/validateLesson) الدرسَ المُصرَّف مقابل ملفات
كل خطوة بعد حلّها، كتسليط ضوء على ملف ليس في الخطوة أو على سطر بعد نهايته. وهما يبلّغان عن مشكلات مختلفة، فشغّلهما معًا. تذكر
مشكلات التحقق الفصل والخطوة والمسار، لا السطر؛ فاستخدم `locate()` من النتيجة لإعادتها إلى سطر.

```typescript
import { parseLesson, validateLesson } from '@karagoz/hayali/parse'

const { lesson, issues, locate } = parseLesson(markdown)
for (const issue of issues) console.log(`${issue.line}: ${issue.rule} ${issue.message}`)

if (!issues.some((issue) => issue.severity === 'error')) {
  for (const issue of validateLesson(lesson)) {
    const line = locate({ chapterId: issue.chapterId, stepId: issue.stepId, path: issue.path }) ?? 1
    console.log(`${line}: ${issue.rule} ${issue.message}`)
  }
}
```
