# الإعداد

يتألف إعداد Karagöz Hayali من أربع خطوات: التثبيت، والتقديم بالترويسات الصحيحة، واستيراد الأنماط، ودمج الترجمات.

## التثبيت

ثبّت الحزم التالية باستخدام مدير الحزم المفضّل. يعتمد Hayali على Karagöz Sandbox، ويحتاج إلى `vue` و`vue-i18n` كاعتماديات
نظيرة (Peer Dependencies).

```shell
# NPM
npm install --save @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# PNPM
pnpm add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Yarn
yarn add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Bun
bun add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n
```

## العزل عبر المصادر (Cross-Origin Isolation)

تعمل Sandbox على WebContainers، وهي تتطلب أن تكون الصفحة معزولة عبر المصادر. قدّم الصفحة بالترويسات التالية:

```
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Opener-Policy: same-origin
```

يفرض `require-corp` قيودًا أيضًا على الموارد من مصادر أخرى (الصور والخطوط والسكربتات) في الصفحة: إذ تحتاج إلى ترويسة
`Cross-Origin-Resource-Policy` مناسبة أو إلى CORS. في أثناء التطوير يسجّل Hayali تحذيرًا واحدًا إذا لم تكن الصفحة معزولة عبر
المصادر. وللاطلاع على إعدادات Vite وNuxt، راجع [إعداد Karagöz Sandbox](/sandbox/setup).

## الأنماط

استورد أنماط الحزم الثلاث كلها، مثلًا في ملف الأنماط الرئيسي:

```css
/* main.css */
@import "@karagoz/shared/dist/karagoz-shared.css";
@import "@karagoz/sandbox/dist/karagoz-sandbox.css";
@import "@karagoz/hayali/dist/karagoz-hayali.css";
```

إذا كنت تصيّر على الخادم، فتأكد من أن ملفات الأنماط هذه جزء من المخرجات المصيَّرة على الخادم. فالتخطيط عند أول عرض يُحدَّد
بـ CSS وحده، وغياب أي ملف أنماط يظهر على شكل درس (Lesson) بلا تنسيق.

## التدويل (I18N)

يستخدم Hayali المكتبة `vue-i18n`. الكائن `i18nMessages` حزمة لغوية كاملة للعربية والألمانية والإنجليزية، و**تتضمن رسائل
Sandbox أصلًا**، فيكفي دمج كائن واحد. وتقع جميع المفاتيح تحت جذر واحد هو `krgz` (`krgz.dir` و`krgz.sandbox.*` و`krgz.hayali.*`).

```typescript
/* i18n.ts */
import { createI18n } from 'vue-i18n'
import { i18nMessages } from '@karagoz/hayali'

export const createAppI18n = (locale: string) =>
  createI18n({
    locale,
    fallbackLocale: 'en',
    messages: {
      ar: { ...i18nMessages.ar },
      de: { ...i18nMessages.de },
      en: { ...i18nMessages.en },
    },
  })
```

## توفير WebContainer

تحصل Sandbox على WebContainer عبر `provideWebContainer()`. يُقلع `useSandboxBoot()` الحاوية عند التركيب (Mount) فقط، ما
يجعل استدعاءه آمنًا أثناء التصيير على الخادم:

```vue
<script setup lang="ts">
import { KrgzHayali, type Lesson } from '@karagoz/hayali'
import { provideWebContainer, useSandboxBoot } from '@karagoz/sandbox'
import { onBeforeUnmount, ref } from 'vue'

defineProps<{ lesson: Lesson }>()

const position = ref({ chapterId: 'intro', stepId: 'welcome' })

const { boot } = useSandboxBoot()
provideWebContainer(boot)
onBeforeUnmount(() => void boot.then((container) => container.teardown()))
</script>

<template>
  <KrgzHayali :lesson="lesson" v-model:position="position" />
</template>
```

لا يمكن تشغيل سوى WebContainer واحد في كل مرة. أنهِ تشغيله عند إزالة المكوّن كما في المثال أعلاه؛ وإلا فسيُقلع عند العودة إلى
الصفحة WebContainer ثانٍ، ويُبلّغ المتصفح بالرسالة *Only a single WebContainer instance can be booted*.

## مسؤوليات المستخدم

يترك Hayali الأمور التالية إليك عن قصد:

* **الترويسات.** قدّم COOP/COEP كما هو موضّح أعلاه.
* **الأنماط في مخرجات SSR.** ضمّن ملفات الأنماط `@karagoz/*` في الصفحات المصيَّرة على الخادم.
* **نسخة جديدة من `vue-i18n` لكل تطبيق أو طلب.** أنشئ نسخة i18n لكل طلب على الخادم، وادمج `i18nMessages`، وخذ اللغة من
  خاصية (Prop) أو من إطار العمل. لا يقرأ Hayali `localStorage` أبدًا.
* **الموضع.** مرّر `position` (زوجًا من `{ chapterId, stepId }`) عبر `v-model:position`. وإن لم يُمرَّر فتُستخدم أول خطوة
  في أول فصل (Chapter). أما حفظ الموضع (في الرابط أو التخزين) فمن شأنك.
