# Arbeiten mit Panels

## Vorhandene Panels

Karagöz Sandbox stellt 4 Panels bereit:
1. Code: zeigt den Datei-Explorer (sofern nicht ausgeblendet) und die aktuell geöffneten Editoren.
2. Ergebnis: zeigt den Vorschau-Frame und die Adressleiste (sofern aktiviert).
3. Prozesse: zeigt laufende und beendete Prozesse.
4. Terminals: zeigt die geöffneten Shell-Terminals (`jsh` &mdash; eine eigene Shell, die bei der WebContainer API 
   bereits mitgeliefert wird).

Diese 4 Panels gehören zu 2 Gruppen, jede mit ihrer eigenen Sichtbarkeitsregel:
* **Haupt-Panels** (Code, Ergebnis): mindestens eines muss immer angezeigt werden. Sie können auch nebeneinander 
  angezeigt werden.
* **Drawer-Panels** (Prozesse, Terminal): schließen sich gegenseitig aus &mdash; wird eines angezeigt, wird das 
  andere ausgeblendet &mdash; und beide können gleichzeitig ausgeblendet sein.

Die Panels werden über 2 Models von `KrgzSandbox` gesteuert:
* `availablePanels`: legt fest, welche Panels verfügbar sind, und damit auch, welche Toggles angezeigt werden, 
  mit denen Panels ein- und ausgeblendet werden können.
  <br>
  Standard: `['code', 'processes', 'result', 'terminal']` (alle Panels sind verfügbar).
* `shownPanels`: legt fest, welche Panels anfangs angezeigt werden.
  <br>
  Standard: `['code', 'result']`.

```html
<!-- show toggles for all panels and show all panels initially -->
<KrgzSandbox
        :available-panels="['code', 'processes', 'result', 'terminal']"
        :shown-panels="['code', 'processes', 'result']"
/>

<!-- show toggles for "code" and "result" and show only the "result" panel initially -->
<KrgzSandbox
        :available-panels="['code', 'result']"
        :shown-panels="['result']"
/>
```

::hint
Da Code/Ergebnis und Prozesse/Terminal unterschiedlichen Sichtbarkeitsregeln folgen, kann ein anfänglicher 
`shownPanels`-Wert widersprüchlich sein. Karagöz Sandbox löst das einmalig auf, wenn die Sandbox eingerichtet wird:
* Enthält `shownPanels` **beide** Drawer-Panels (`processes` und `terminal`), wird nur dasjenige behalten, das 
  **zuletzt** im Array steht.
* Enthält `shownPanels` danach **keines** der Haupt-Panels (weder `code` noch `result`), wird `code` hinzugefügt, 
  damit immer ein Haupt-Panel sichtbar ist.

Diese Auflösung erfolgt nur einmal für den Anfangswert &mdash; spätere Toggles respektieren immer die oben 
beschriebenen Ausschlussregeln.
::

## Layout

### Desktop

In ausreichend breiten Containern (siehe [`multiPanelFrom`](/sandbox/handbook/props-and-events#multipanelfrom)) 
rendert `KrgzSandbox` ein Layout mit 4 Zeilen:
1. **Haupt-Toolbar**: Toggles für Code und Ergebnis sowie die Aktionsbuttons für Lösen, Vollbild und Theme (jeder 
   davon lässt sich einzeln ausblenden, siehe [Props](/sandbox/handbook/props-and-events)).
2. **Haupt-Panels**: der Inhalt des Code- und/oder Ergebnis-Panels, in der Größe veränderbar und nebeneinander 
   angezeigt, wenn beide sichtbar sind.
3. **Drawer-Toolbar**: Toggles für Prozesse und Terminal sowie ein Icon zum Schließen/Öffnen, das den gesamten 
   Drawer ein- oder ausklappt. Diese Zeile (und Zeile 4) wird nur gerendert, wenn mindestens ein Drawer-Panel 
   verfügbar ist.
4. **Drawer**: der Inhalt des Prozess- oder Terminal-Panels, nur gerendert, solange ein Drawer-Panel angezeigt wird.

### Mobil

Unterhalb der konfigurierten Breite (oder bei `multiPanelFrom="none"`) wechselt `KrgzSandbox` zu einem 
Single-Panel-Layout, das für Mobilgeräte ausgelegt ist, anstatt das 4-zeilige Layout einfach zu verkleinern:
* Eine minimale Leiste oben mit einem Overflow-Menü für die Aktionen Lösen, Theme und Vollbild.
* Der Inhaltsbereich, der immer genau ein Panel anzeigt.
* Eine Tab-Leiste unten mit einem Toggle pro verfügbarem Panel (Code, Ergebnis, Prozesse, Terminal). Ein Tipp auf 
  einen Tab zeigt dieses Panel an, unabhängig davon, ob es auf dem Desktop ein Haupt- oder Drawer-Panel ist 
  &mdash; mobil gibt es keine Unterscheidung zwischen Haupt- und Drawer-Panels, nur ein einziges aktives Panel.

::hint
`shownPanels` kann im mobilen Layout weiterhin mehr als ein Panel enthalten (z. B. wie für den Desktop 
konfiguriert); nur der erste Eintrag bestimmt, welches Panel anfangs angezeigt wird. Ein Tipp auf einen Tab in der 
unteren Leiste verschiebt dieses Panel an den Anfang der Liste.
::

## Panel-Komponenten

`KrgzSandbox` rendert die Inhalte der Panels wie folgt in Slots:

| Slot        | Komponente                             | Rolle                                        |
|-------------|----------------------------------------|----------------------------------------------|
| `explorer`  | `<KrgzExplorer />`                     | Der Datei-Explorer im Code-Panel.            |
| `editor`    | `<KrgzEditorTabs />`                   | Die geöffneten Editoren im Code-Panel.       |
| `preview`   | `<KrgzPreview />`                      | Der Vorschau-Frame mit der Adressleiste.     |
| `processes` | `<KrgzProcessTabs mode="process" />`   | Laufende und beendete Prozesse.              |
| `terminal`  | `<KrgzProcessTabs mode="terminal" />`  | Geöffnete Terminals.                         |

Diese Komponenten erhalten alles, was sie brauchen, über den Aufruf von `useKaragozSandbox()`. Deshalb nehmen sie 
keine Props entgegen (mit Ausnahme der Prop `mode` von `KrgzProcessTabs`).

Das sorgt für mehr Flexibilität und ermöglicht die folgenden Szenarien:

### Panels ersetzen

Du kannst einzelne oder alle Panel-Komponenten ersetzen und trotzdem die von `KrgzSandbox` bereitgestellte Struktur 
samt ihrer Funktionalität (Toggles, größenveränderbare Panels, zusätzliche Funktionsbuttons) weiter nutzen.

```html
<KrgzSandbox>
  <template #explorer>
    <MyExplorer />
  </template>
  <template #editor>
    <MyEditor />
  </template>
  <template #preview>
    <MyPreview />
  </template>
  <template #processes>
    <MyProcesses />
  </template>
  <template #terminal>
    <MyTerminal />
  </template>
</krgzSandbox>
```

Als praktisches Beispiel ersetzen wir den Standard-Explorer durch eine einfache Liste, um eine HTML-, eine 
JavaScript- und eine CSS-Datei zu bearbeiten.

```vue
<script setup lang="ts">
const { boot, isBooting } = useSandboxBoot()
provideWebContainer(boot)

const sandbox = useSandbox()

// ... omitted for readability 
</script>

<template>
  <KrgzSandbox :booting="isBooting" hide-solve-button>
    <template #explorer>
      <div class="p-1 text-sm">
        Your files:
        <ul class="list-disc list-inside">
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/index.html')">HTML</a>
          </li>
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/script.js')">JS</a>
          </li>
          <li>
            <a @click.prevent="sandbox.editorTabs.open('./public/style.css')">CSS</a>
          </li>
        </ul>
      </div>
    </template>
  </KrgzSandbox>
</template>
```

### KrgzSandbox selbst ersetzen

Du kannst die bereitgestellten Panel-Komponenten auch verwenden, ohne dich an das Standard-Layout und die 
Funktionalität von `KrgzSandbox` zu halten.

Das folgende Beispiel rendert den Editor und das Ergebnis in einem einfachen `div`-Element, ohne `KrgzSandbox` zu 
verwenden.

```vue
<template>
  <div class="grid grid-cols-2 h-full">
    <div class="border-r">
      <KrgzEditorTabs v-if="!isBooting" />
    </div>
    <div>
      <KrgzPreview v-if="!isBooting" />
    </div>
  </div>
</template>
```
