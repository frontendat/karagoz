# Prozess-Tabs

Die Eigenschaft `processTabs` der Sandbox ist für die Verwaltung von Prozessen und Terminals zuständig.

## Automatisches Bootstrapping

In einfachen Anwendungsfällen musst du Prozesse nicht direkt verwalten.
Karagöz Sandbox bietet die Funktion `bootstrap`, die Folgendes erledigt:
1. Beendet den Prozess zur Installation der Abhängigkeiten und den Dev-Server, falls einer von beiden läuft.
2. **Beim ersten Durchlauf:** lauscht auf URL-Änderungen im Vorschau-iframe, um die aktuelle URL an das 
   übergeordnete Fenster zu senden. Das ist nötig, um die aktuelle URL in der Adressleiste der Vorschau anzuzeigen.
3. Öffnet ein Terminalfenster, sofern die Sandbox-Optionen das erlauben.
4. Installiert die Abhängigkeiten (mit dem in den Optionen konfigurierten Paketmanager).
5. Startet den Dev-Server (ebenfalls mit dem in den Optionen konfigurierten Paketmanager).
6. **Beim ersten Durchlauf:** überwacht das aktuelle Arbeitsverzeichnis, um ein erneutes Bootstrapping auszulösen, 
   wenn sich eine Datei ändert, die eine Neuinstallation erfordert (z. B. `package.json`).

## Manuelle Prozessverwaltung

Du kannst auf das automatische Bootstrapping verzichten, indem du `sandbox.bootstrap()` einfach nicht aufrufst. Dann 
hast du die volle Kontrolle darüber, welche Prozesse in welcher Reihenfolge laufen.

## Einen Prozess starten

Unabhängig davon, ob du das automatische Bootstrapping nutzt oder nicht, kannst du Prozesse manuell starten, indem 
du `processTabs.open()` aufrufst.

```ts
sandbox.processTabsopen(
  // Unique id. As a convention, you can use the string presentation of the command to run.
  'npm install',
  
  // Optional label to show for the process tab. 
  // If not provided, the process tab ID is shown instead.
  'Install', 
     
  // Optional context.
  {
     // The only mandatory property. The command to spawn the process with.
     command: 'npm',
     // Additional arguemtns.
     arguments: ['install', '--frozen-lockfile'],
     
     // Flags to enable/disable certain UI features (all false by default).
     canRestart: false,
     canStop: false,
     isHidden: false,
     suppressClose: false,
     suppressInput: false,
     
     // When true, the process is treated as a terminal: 
     // some flags are ignored and the tab will be shown in the
     // terminals panel and not in the processes panel.
     isTerminal: false,
  },
)
```

Das Kontext-Objekt hat einige weitere Eigenschaften, die intern verwendet werden.
Mehr dazu erfährst du in der [API-Referenz](/sandbox/api-reference/type-aliases/processtabcontext).

Wenn du eine ID übergibst, die bereits existiert, wird der entsprechende Prozess-Tab fokussiert, ohne einen neuen 
Prozess zu starten.

## Einen Prozess stoppen

Du kannst einen Prozess stoppen, indem du entweder
* `sandbox.processTabs.close(id)` aufrufst, was den Prozess beendet und seinen Tab schließt,
* oder `sandbox.processTabs.kill(id)` aufrufst, was den Prozess beendet, seinen Tab aber sichtbar lässt, damit die 
  Ausgabe weiterhin zugänglich bleibt.

## Einen Prozess neu starten

Ein Prozess kann mit `sandbox.processTabs.restart(id)` neu gestartet werden.

Außerdem zeigen Prozesse, deren Kontext `canRestart: true` enthält, einen Neustart-Button an, mit dem der Prozess 
über die UI neu gestartet werden kann.

## Beispiel: Manuelles Bootstrapping

Lass uns alles zusammenführen und Prozesse manuell starten.

In der Demo unten wird kein Prozess automatisch gestartet. Stattdessen gibt es Buttons, um:
* die Installation der Abhängigkeiten auszulösen,
* den Entwicklungsserver zu starten,
* ein Terminal zu öffnen,
* das Terminal zu schließen, falls es geöffnet ist.

Hier ist der Code, der diese Prozesse steuert:

```ts
const installDeps = async () => {
  await sandbox.processTabs.open('npm install', 'Install Dependencies', {
    command: 'npm',
    args: ['install'],
    suppressClose: true,
    suppressInput: true,
  })
  // we await to correctly set installationCompleted flag
  await sandbox.processTabs.findTab('npm install')?.context?.process?.exit
  installationCompleted.value = true
}

const startDevServer = () => {
  sandbox.processTabs.close('npm install')
  // No need to await here because nothing depends on finishing this process
  sandbox.processTabs.open('npm start', 'Dev Server', {
    command: 'npm',
    args: ['start'],
    canRestart: true,
    canStop: true,
    suppressInput: true,
  })
}

const openTerminal = () => {
  sandbox.processTabs.open('terminal', 'Terminal', {
    command: 'jsh',
    isTerminal: true,
  })
}

const closeTerminal = () => {
  sandbox.processTabs.close('terminal')
}
```

## Beispiel: Generatoren verwenden

Ein guter Anwendungsfall für manuelles Bootstrapping (oder dafür, einige Prozesse vor dem automatischen 
Bootstrapping auszuführen) ist die Verwendung von Generatoren (z. B. `npm create`, `create-react-app` usw.).

Im folgenden Beispiel erzeugen wir eine Vite-App mit dem React-Template, indem wir folgenden Befehl ausführen:
```shell
npm create vite@latest my-react-app -- --template react
```

Dabei gibt es ein paar Dinge zu beachten:
* Karagöz Sandbox erwartet die Dateien im aktuellen Arbeitsverzeichnis, während Generatoren (meistens) ein neues 
  Verzeichnis für die erzeugten Dateien anlegen. Deshalb müssen wir nach der Generierung alle Dateien in das 
  aktuelle Arbeitsverzeichnis verschieben und (optional) das nun leere Verzeichnis des Generators entfernen.
* Wir sollten versuchen, Benutzereingaben überflüssig zu machen, indem wir die Optionen des Befehls direkt 
  übergeben. Das funktioniert nicht in jedem Fall, ist aber empfehlenswert.
* Manche Generatoren führen unerwünschte Schritte aus, die sich nicht verhindern lassen (z. B. initialisiert der 
  Analog-Generator ein Git-Repository, was in einem WebContainer nicht funktioniert).

Unser Ablauf für das Beispiel sieht also so aus:
1. Einen Prozess starten, der den oben gezeigten `npm create`-Befehl ausführt.
2. Alle erzeugten Dateien von `./my-react-app` nach `.` verschieben.
3. Das Verzeichnis `./my-react-app` entfernen.
4. Das automatische Bootstrapping ausführen, um die Abhängigkeiten zu installieren und den Entwicklungsserver zu 
   starten.

Damit sieht unser `onMounted`-Hook ungefähr so aus:

```ts
onMounted(async () => {
  // Ensure injected promise has been resolved
  const container = await boot
  
  // Mount shell script to perform extra steps before bootstrapping
  await container.mount({
    'prepare.sh': {
      file: {
        contents: [
          'mv ./my-react-app/* ./my-react-app/.* ./',
          'rmdir ./my-react-app',
          'rm prepare.sh',
        ].join('\n'),
      },
    },
  })
  
  // Set start script
  sandbox.setOption('process', (old) => ({
    ...old,
    commands: {
      ...old.commands,
      devServer: 'npm run dev',
    },
  }))
  
  // Generate react app
  await sandbox.processTabs.open('npm create', 'Generating React App', {
    command: 'npm',
    args: 'create vite@latest my-react-app -y -- --template react'.split(' '),
    suppressClose: true,
    suppressInput: true,
  })
  await sandbox.processTabs.findTab('npm create')?.context?.process?.exit
  sandbox.processTabs.close('npm create')
  
  // Perform remaining steps before bootstrapping
  await sandbox.processTabs.open('prepare', 'Prepare', {
    command: 'jsh',
    args: ['prepare.sh'],
    isHidden: true,
  })
  
  // Hand over to bootstrap()
  await sandbox.bootstrap()
  
  sandbox.editorTabs.open('./src/App.jsx')
})
```
