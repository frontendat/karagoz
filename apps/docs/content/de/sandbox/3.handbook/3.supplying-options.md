# Optionen übergeben

Die von `useSandbox` zurückgegebene Sandbox stellt eine Methode `setOption` bereit, mit der du Optionen für einen 
bestimmten Bereich der Sandbox setzen kannst. Dazu übergibst du einen Schlüssel und den Wert oder einen Callback, der 
den neuen Wert aus dem alten berechnet. Zum Beispiel:

```ts
sandbox.setOption('editor', { suppressClose: true })
// or
sandbox.setOption('editor', old => ({ ...old, suppressClose: true }))
```

::hint
Auf dieser Seite gehen wir auf einige Optionen genauer ein. Die vollständige Dokumentation aller Optionen findest du 
in der API-Dokumentation (siehe [SandboxOptions](/sandbox/api-reference/type-aliases/sandboxoptions)).
::

Eine **schreibgeschützte** Kopie der Optionen erhältst du einfach über die Eigenschaft `options` der 
Sandbox-Instanz:

```ts
// DO NOT try to set options through assignment here;
// use sandbox.setOption() instead.
sandbox.options.editor
sandbox.options.explorer
sandbox.options.preview
sandbox.options.process
sandbox.options.terminal
```

## Editor-Optionen

**Schlüssel: `editor`**

Die Editor-Optionen umfassen:
1. `suppressClose`: wenn `true`, wird das „Schließen“-Icon bei Editor-Tabs nicht angezeigt. Dieses Verhalten kann für 
   einzelne Editor-Tabs überschrieben werden.
2. `theme`: legt die Themes fest, mit denen die CodeMirror-Editoren gestaltet werden. Es nimmt 2 Callbacks für das 
   helle und das dunkle Theme entgegen.

## Explorer-Optionen

**Schlüssel: `explorer`**

Die Explorer-Optionen bestehen aus 3 Gruppen von Pfad-Matchern. Hier sind sie mit ihren Standardwerten:
```ts
sandbox.setOption('explorer', {
  /* determine whether an entity (directory or file) should be hidden in the file explorer. */
  hidden: ['./node_modules/*'],
  /* determine whether an entity should be marked as readonly in the file explorer and editor tabs (lock icon). */
  readonly: [
    '*/node_modules',
    '*/package-lock.json',
    '*/pnpm-lock.yaml',
    '*/yarn.lock',
  ],
  /* determine whether changing an entity should trigger the re-installation of dependencies and re-bootstrapping. */
  reinstall: ['./package.json'],
})
```

## Vorschau-Optionen

**Schlüssel: `preview`**

Die Vorschau-Optionen umfassen:
1. `suppressAddressBar`: wenn `true`, wird die Adressleiste über dem Vorschau-Frame nicht gerendert.
2. `suppressConsole`: wenn `true`, wird der Konsolen-Toggle neben dem Neu-laden-Icon der Adressleiste nicht 
   gerendert. Das Konsolen-Panel, das die Ausgaben von `console.log`/`info`/`warn`/`error`/`debug` sowie nicht 
   abgefangene Fehler aus der Vorschau anzeigt, lässt sich unabhängig von dieser Option weiterhin programmatisch über 
   `sandbox.preview.showConsole()` und `sandbox.preview.hideConsole()` steuern. Seinen aktuellen Zustand kannst du 
   über `sandbox.preview.consoleShown` auslesen.

## Prozess-Optionen

**Schlüssel: `process`**

Enthält 3 Optionen: `packageManager`, `commands` und `starters`.

`packageManager` legt den Paketmanager fest, den die Befehle verwenden. Nur relevant, wenn `commands` und `starters` 
die Standardwerte verwenden. Einer von `npm`, `pnpm` und `yarn`.

Der Paketmanager muss gesetzt werden, bevor `sandbox.bootstrap()` aufgerufen wird.

`commands` ist ein Objekt mit 3 Schlüsseln: `install`, `devServer` und `terminal`. Sie enthalten die Shell-Befehle, 
die für die Standardprozesse ausgeführt werden. `install` und `devServer` werden automatisch angepasst, wenn die 
Option `packageManager` geändert wird.

Entsprechend enthält `starters` dieselben 3 Schlüssel `install`, `devServer` und `terminal`, in diesem Fall sind es 
aber Callbacks, die die jeweiligen Prozesse starten. Standardmäßig verwenden sie ihre Gegenstücke aus `commands`. Das 
bedeutet auch: Wird einer der Schlüssel von `starters` gesetzt, wird sein Gegenstück in `commands` ignoriert.

```ts
sandbox.setOption('process', (old) => ({
  packageManager: 'pnpm', // so commands.install = "pnpm install" and commands.devServer = "pnpm start" 
  commands: {
    ...old.commands,
    devServer: 'pnpm dev', // overriding devServer command default
  },
  starters: {
    ...old.starters,
    terminal: () => { /* new terminal process logic */ }
  },
}))
```

## Terminal-Optionen

**Schlüssel: `terminal`**

Die Terminal-Optionen umfassen:
1. `maxCount`: die maximale Anzahl gleichzeitig geöffneter Terminal-Tabs. Standard: 3.
2. `theme`: legt die Themes fest, mit denen XTerm gestaltet wird. Es nimmt 2 Callbacks für das helle und das dunkle 
   Theme entgegen.
