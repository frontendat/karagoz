# Props und Events


## Props

Neben den Panel-Models akzeptiert `KrgzSandbox` einige Flags, um die Sichtbarkeit bestimmter Features anzupassen:

### `booting`

Wenn auf `true` gesetzt, wird eine Ladeanzeige eingeblendet. Es ist wichtig, diese Prop zu übergeben, damit keine 
Panels gerendert werden, bevor der WebContainer bereit ist.

### `hideExplorer`

Wenn auf `true` gesetzt, wird der Datei-Explorer ausgeblendet (z. B. um nur eine bestimmte Auswahl an Editor-Tabs 
anzuzeigen).

### `hideFullScreenToggle`

Wenn auf `true` gesetzt, wird der Vollbild-Toggle ausgeblendet.

### `hideSolveButton`

Wenn auf `true` gesetzt, wird der Lösen-Button ausgeblendet, falls er nicht benötigt wird.

### `hideThemeToggle`

Wenn auf `true` gesetzt, wird der Toggle für das helle/dunkle Theme ausgeblendet.

### `multiPanelFrom`

Legt fest, ab welcher Containerbreite `KrgzSandbox` zwischen seinen 2 Layouts wechselt (siehe 
[Arbeiten mit Panels](/sandbox/handbook/working-with-panels#layout)):
* **Desktop-Layout:** das 4-zeilige Layout mit Haupt-Toolbar/-Panels und Drawer-Toolbar/-Panel.
* **Mobiles Layout:** ein Single-Panel-Layout mit einem Overflow-Menü oben und einer Tab-Leiste unten zum Wechseln 
  der Panels.

<br>

* **Mögliche Werte:** <br> `none`, `xs`, `sm`, `md`, `lg`, `xl`, `2xl`, `3xl`, `4xl`, `5xl`, `6xl`, `7xl`
* Der Wert bestimmt die minimale Containerbreite, ab der das Desktop-Layout verwendet wird. Dafür wird
  :external-link{href='https://github.com/tailwindlabs/tailwindcss-container-queries' content='tailwindcss-container-queries'} 
  verwendet.
* Der zusätzliche Wert `none` erzwingt unabhängig von der Containerbreite das mobile Single-Panel-Layout.
* Wird kein Wert oder `undefined` übergeben, wird immer das Desktop-Layout verwendet.
* Im mobilen Layout wird anfangs das erste Panel aus `shown-panels` angezeigt. Danach wird das zuletzt getoggelte 
  Panel angezeigt (getoggelte Panels werden an den Anfang von `shown-panels` verschoben).

## Events

`KrgzSandbox` emittiert nur ein einziges Event.

### `solve`

Wird emittiert, wenn auf den Lösen-Button geklickt wird (sofern er nicht ausgeblendet ist).

Es gibt keine festgelegte Art, dieses Event zu behandeln. Üblicherweise werden dabei aber neue Dateien im 
WebContainer gemountet oder bestehende Dateien neu gemountet, um das gewünschte Ergebnis anzuzeigen.

```vue
<script setup lang="ts">
const onSolveClick = async () => {
  sandbox.container.value?.mount({
    public: {
      directory: {
        "about.html": {
          file: {
            contents: "..."
          }
        },
        "index.html": {
          file: {
            contents: "..."
          }
        }
      }
    }
  })
}
</script>

<template>
  <KrgzSandbox
    :booting="isBooting"
    @solve="onSolveClick()"
  ></KrgzSandbox>
</template>
```

Im folgenden Beispiel lädt ein Klick auf den Lösen-Button einen entfernten `FileSystemTree` von einem 
Server-Endpunkt und mountet ihn im WebContainer. Dadurch erhält `index.html` eine Navigationsleiste oben, und eine 
zusätzliche Seite `about.html` wird erstellt.
