# Entfernte Snapshots mounten

Die Inhalte der zu mountenden Dateien direkt im Code anzugeben, reicht zum Lernen und Experimentieren völlig aus. 
Du wirst aber schnell in eine Situation kommen, in der du mehr Flexibilität brauchst.

Außerdem ist es in einem echten Projekt immer sinnvoll, deine Daten (in diesem Fall die zu mountenden Dateien) von 
der Logik (der Vue-Komponente mit der Karagöz Sandbox) zu trennen.

Genau dann sind entfernte Snapshots praktisch.

Schauen wir uns 2 Situationen an. Bei beiden werden API-Endpunkte in einer Nuxt-Site erstellt (ähnlich wie diese 
Dokumentation ^^). Wir hätten also folgende Dateistruktur:

```
site-root
|_ server
| |_ api
|   |_ snapshot
|     |_ [snapshot].get.ts      <- Server endpoint
|_ assets
  |_ snapshots
    |_ express                  <- Snapshot "express"
    | |_ public
    | | |_ index.html
    | | |_ script.js
    | | |_ style.css
    | |_ package.json
    | |_ server.js
    |_ express-solve            <- Snapshot "express-solve"
      |_ public
        |_ about.html
        |_ index.html
```

Wenn wir also den Server-Endpunkt `GET /api/snapshot/express` aufrufen, sollten wir den Inhalt des Verzeichnisses 
`server/assets/snapshots/express` erhalten, bereit zum Mounten im WebContainer.

Entsprechend würde `GET /api/snapshot/express-solve` den Inhalt von `server/assets/snapshots/express-solve` 
zurückgeben.

## 1. Zugriff auf das Dateisystem ist möglich

Wenn deine Site auf einem Node-Server läuft, auf den du Dateien hochladen und jederzeit darauf zugreifen kannst, hast 
du Glück. Genau dafür gibt es ein praktisches Hilfsmittel &ndash;veröffentlicht von StackBlitz&ndash;.

Du musst nur
:external-link{href='https://www.npmjs.com/package/@webcontainer/snapshot' content='@webcontainer/snapshot'} als 
Abhängigkeit installieren und dann `[snapshot].get.ts` wie folgt anpassen.

```ts
import { snapshot } from '@webcontainer/snapshot'
import { defineEventHandler } from 'h3'

// Restrict snapshots to a fixed list as a simple security measure.
const snapshots = ['express', 'express-solve']

export default defineEventHandler(async (event) => {
  // The snaphost name passed in the [snapshot] parameter of the endpoint path.
  const snapshotName = getRouterParam(event, 'snapshot')
  
  // 404 - Someone is trying to access a snapshot that is not in the list.
  if (snapshotName && !snapshots.includes(snapshotName)) {
    throw createError({
      statusCode: 404,
      statusMessage: 'Snapshot not found',
    })
  }

  try {
    // Where the magic happens. Simply pass the directory path to the snapshot() function.
    const sourceSnapshot = await snapshot(`./server/assets/snapshots/${snapshotName}`)
    // Set the correct content-type.
    event.headers.set('content-type', 'application/octet-stream')
    // Return the resulting snaphost.
    return sourceSnapshot
  } catch (error) {
    // Something went wrong.
    throw createError({
      statusCode: 500,
      statusMessage: 'Unable to get snapshot',
    })
  }
})
```

In deiner Sandbox-Komponente kannst du die Snapshots dann wie unten gezeigt mit `useFetch()` abrufen.

```vue
<script setup lang="ts">
import {
  KrgzSandbox,
  provideWebContainer,
  useSandbox,
  useSandboxBoot,
} from '@karagoz/sandbox'
import { onBeforeUnmount, onMounted } from 'vue'

const { boot, isBooting } = useSandboxBoot()
provideWebContainer(boot)

const sandbox = useSandbox()

const { data: initialSnapshot } = await useFetch<Response>(
  '/api/snapshot/express',
  {
    // These options are important when working with snapshots.
    headers: { Accept: 'application/octet-stream' },
    responseType: 'blob',
  },
)

const { data: solveSnapshot, execute: fetchSolveSnapshot } =
  await useFetch<Response>('/api/snapshot/express-solve', {
    immediate: false,
    // These options are important when working with snapshots.
    headers: { Accept: 'application/octet-stream' },
    responseType: 'blob',
  })

onMounted(async () => {
  if (!initialSnapshot.value) return
  // Ensure injected promise has been resolved
  const container = await boot
  // Continue initialisation
  await container.mount(await initialSnapshot.value.arrayBuffer()) // Remember to call arrayBuffer()
  await sandbox.bootstrap()
  sandbox.editorTabs.open('./public/index.html')
})

onBeforeUnmount(() => sandbox.container.value?.teardown())

const onSolveClick = async () => {
  await fetchSolveSnapshot()
  if (!solveSnapshot.value) return
  sandbox.container.value?.mount(await solveSnapshot.value.arrayBuffer()) // Remember to call arrayBuffer()
}
</script>

<template>
  <KrgzSandbox
    :booting="isBooting"
    :shown-panels="['code', 'processes', 'result']"
    @solve="onSolveClick()"
  ></KrgzSandbox>
</template>
```

## 2. Kein Zugriff auf das Dateisystem

Wenn du eine serverseitig gerenderte Nuxt-Site bei einem Anbieter wie Cloudflare oder Vercel deployst, läuft dein 
Code im Kontext einer Server-Funktion und hat keinen dauerhaften Zugriff auf das Dateisystem. Die oben beschriebene 
Lösung funktioniert dann also nicht.

Aber keine Sorge, es gibt eine Lösung – sie erfordert nur etwas mehr Code.

Dein Verzeichnis `server/assets` wird von der Storage-Schicht von Nuxt erfasst und ist über 
`useStorage('assets:server')` zugänglich. Damit müssen wir nur die relevanten Storage-Schlüssel durchlaufen, daraus 
ein `FileSystemTree`-Objekt erstellen und es als JSON zurückgeben (in diesem Fall also nicht als ArrayBuffer).

Genau so wird es auf dieser Site umgesetzt. Du kannst dir den Code direkt auf GitHub ansehen:
* [Snapshot-Endpunkt](https://github.com/frontendat/karagoz/blob/main/apps/docs/server/api/snapshot/%5Bsnapshot%5D.get.ts)
* [Sandbox-Komponente](https://github.com/frontendat/karagoz/blob/main/apps/docs/components/content/sandbox/demo/SandboxDemoFull.vue)
