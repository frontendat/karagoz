# Einrichtung

Die Einrichtung von Karagöz Hayali besteht aus vier Schritten: installieren, mit den richtigen Headern ausliefern, die
Styles importieren und die Übersetzungen zusammenführen.

## Installation

Installiere die folgenden Pakete mit deinem bevorzugten Paketmanager. Hayali baut auf Karagöz Sandbox auf und benötigt
`vue` und `vue-i18n` als Peer-Abhängigkeiten.

```shell
# NPM
npm install --save @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# PNPM
pnpm add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Yarn
yarn add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n

# Bun
bun add @karagoz/hayali @karagoz/sandbox @karagoz/shared vue-i18n
```

## Cross-Origin-Isolation

Die Sandbox läuft auf WebContainern, und die verlangen, dass die Seite Cross-Origin-isoliert ist. Liefere sie mit
diesen Headern aus:

```
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Opener-Policy: same-origin
```

`require-corp` schränkt auch Cross-Origin-Ressourcen (Bilder, Schriften, Skripte) auf der Seite ein: Sie benötigen einen
passenden `Cross-Origin-Resource-Policy`-Header oder CORS. In der Entwicklung gibt Hayali genau eine Warnung aus, wenn die
Seite nicht Cross-Origin-isoliert ist. Die Konfiguration für Vite und Nuxt findest du unter
[Einrichtung von Karagöz Sandbox](/sandbox/setup).

## Styles

Importiere die Styles aller drei Pakete, zum Beispiel in deinem Haupt-Stylesheet:

```css
/* main.css */
@import "@karagoz/shared/dist/karagoz-shared.css";
@import "@karagoz/sandbox/dist/karagoz-sandbox.css";
@import "@karagoz/hayali/dist/karagoz-hayali.css";
```

Wenn du auf dem Server renderst, achte darauf, dass diese Stylesheets Teil der serverseitig gerenderten Ausgabe sind.
Das Layout für den ersten Aufbau wird allein durch CSS bestimmt; fehlt ein Stylesheet, siehst du eine ungestylte Lektion.

## I18N

Hayali verwendet `vue-i18n`. `i18nMessages` ist ein vollständiges Sprachpaket für Englisch, Deutsch und Arabisch, das
**die Sandbox-Texte bereits enthält**, du führst also nur ein einziges Objekt zusammen. Alle Schlüssel liegen unter einer
`krgz`-Wurzel (`krgz.dir`, `krgz.sandbox.*`, `krgz.hayali.*`).

```typescript
/* i18n.ts */
import { createI18n } from 'vue-i18n'
import { i18nMessages } from '@karagoz/hayali'

export const createAppI18n = (locale: string) =>
  createI18n({
    locale,
    fallbackLocale: 'en',
    messages: {
      ar: { ...i18nMessages.ar },
      de: { ...i18nMessages.de },
      en: { ...i18nMessages.en },
    },
  })
```

## Den WebContainer bereitstellen

Die Sandbox erhält ihren WebContainer über `provideWebContainer()`. `useSandboxBoot()` startet ihn nur beim Mounten, sodass
der Aufruf auch beim Rendern auf dem Server sicher ist:

```vue
<script setup lang="ts">
import { KrgzHayali, type Lesson } from '@karagoz/hayali'
import { provideWebContainer, useSandboxBoot } from '@karagoz/sandbox'
import { ref } from 'vue'

defineProps<{ lesson: Lesson }>()

const position = ref({ chapterId: 'intro', stepId: 'welcome' })

provideWebContainer(useSandboxBoot().boot)
</script>

<template>
  <KrgzHayali :lesson="lesson" v-model:position="position" />
</template>
```

## Aufgaben auf deiner Seite

Hayali überlässt dir bewusst Folgendes:

* **Header.** Liefere COOP/COEP wie oben beschrieben aus.
* **Styles in der SSR-Ausgabe.** Binde die `@karagoz/*`-Stylesheets in serverseitig gerenderte Seiten ein.
* **Ein frisches `vue-i18n` pro App bzw. Anfrage.** Erstelle die i18n-Instanz auf dem Server pro Anfrage, führe
  `i18nMessages` zusammen und nimm die Sprache aus einer Prop oder deinem Framework. Hayali liest nie `localStorage`.
* **Die Position.** Übergib `position` (ein Paar aus `{ chapterId, stepId }`) mit `v-model:position`. Ohne Angabe wird der
  erste Schritt des ersten Kapitels verwendet. Die Position zu speichern (URL, Storage) liegt bei dir.
