# Navigation und Zurücksetzen

Lernende bewegen sich mit den Buttons Zurück/Weiter, dem Inhaltsverzeichnis-Dropdown in der Werkzeugleiste oder per Klick
auf einen Schritt in der Schrittliste zwischen den Schritten. Die Schrittliste zeigt die Schritte des aktuellen Kapitels;
Kapitel erreichst du über das Inhaltsverzeichnis.

## Die Position

Der aktuelle Schritt ist das `position`-Model, eine [`Position`](/hayali/api-reference/interfaces/Position) aus
`{ chapterId, stepId }`. Binde es mit `v-model:position`, um es zu lesen, eine gespeicherte Position wiederherzustellen
oder direkt zu einem Schritt zu verlinken. Lässt du es weg, beginnt die Lektion beim ersten Schritt des ersten Kapitels.
Hayali speichert die Position nie selbst.


Schritt-IDs sind nur innerhalb eines Kapitels eindeutig, deshalb besteht eine Position aus `chapterId` und `stepId`
zusammen. Hayali übernimmt kein Routing: Binde das Model an das, was dein Framework bietet, etwa einen Query-Parameter,
einen Hash oder ein Pfadsegment.

Nennt die gebundene Position einen Schritt, den es nicht gibt, zum Beispiel bei einem veralteten Link, zeigt Hayali den
ersten Schritt, schreibt diese Position ins Model zurück, damit sich deine Bindung selbst korrigiert, und gibt in der
Entwicklung eine Warnung aus.

## Deep Links

Binde die Position an deinen Router, damit Schritte verlinkbar werden. Die Demo auf dieser Seite hält sie in einem
Query-Parameter, `?step=chapterID/stepID`:

```ts
const route = useRoute()
const router = useRouter()

// Mit dem ersten Schritt starten, damit die Hydration zum HTML passt, und die URL erst nach dem Mounten anwenden.
const position = ref({ chapterId: 'basics', stepId: 'markup' })
onMounted(() => {
  const linked = parseStep(route.query.step)
  if (linked) position.value = linked
})

// Änderungen mit `replace` zurückschreiben.
watch(position, ({ chapterId, stepId }) => {
  void router.replace({ query: { ...route.query, step: `${chapterId}/${stepId}` } })
})
```

* **Query statt Hash.** Ein Query gehört zur Anfrage und übersteht Pfadwechsel. Ein Hash erreicht den Server nie.
* **Erst nach dem Mounten anwenden.** Vorgerenderte Seiten werden ohne Query ausgeliefert, deshalb muss das erste
  Rendering der Startschritt sein. Würde die Position schon im Setup gesetzt, passte sie nicht zu diesem HTML, und die
  Hydration ließe Werkzeugleiste und Sandbox nicht zum Schritt passen. `onMounted` genügt: Die Sandbox startet mit den
  Dateien des verlinkten Schritts.
* **Sprachpräfixe spielen keine Rolle.** Ein Query ist vom Pfad unabhängig und funktioniert unter `/de/` und `/ar/`
  gleich.
* **Replace statt Push.** Wird das Model von außen gesetzt, entfallen der Bestätigungsdialog und das Zurücksetzen. Ein
  Zurück-Button, der die Position ändert, ließe die Dateien deshalb nicht zum Schritt passen. Lies die URL nur beim
  Laden.
* **Fehlerhafte Links sind unkritisch.** Ein Link auf einen Schritt, den es nicht mehr gibt, zeigt den ersten Schritt
  und korrigiert das Model, sodass sich deine URL selbst heilt.

## Zurücksetzen und der Bestätigungsdialog

Jeder Schritt beginnt in einem bekannten Zustand. Wenn Lernende weitergehen, werden die zurücksetzbaren Dateien auf den
Baum des Zielschritts zurückgesetzt (siehe [Adjustments und Removals](/hayali/handbook/adjustments-and-removals)). Eine
Datei gilt als **geändert** (dirty), sobald Lernende sie bearbeitet haben. Solange Dateien geändert sind, fragt Hayali vor
dem Wechsel zu einem anderen Schritt nach einer Bestätigung, weil die Änderungen verloren gehen.

* **Fortfahren** setzt die Dateien zurück und wechselt.
* **Abbrechen** ändert nichts: nicht die Position, die Dateien, die offenen Tabs oder die Vorschau.

::hint
Nur zurücksetzbare Dateien werden überwacht. Änderungen an [unveränderlichen Dateien](/hayali/handbook/adjustments-and-removals)
machen die Lektion nie „dirty“ und werden nie zurückgesetzt.
::

## Immer nur ein Wechsel

Die Navigation läuft einzeln (Single-Flight). Vom Bestätigungsdialog bis der neue Schritt steht, sind Werkzeugleiste und
Schrittliste deaktiviert, und weitere Navigationsanfragen werden ignoriert; sie werden nicht in eine Warteschlange
gestellt. Editor- und Vorschau-Direktiven werden danach im Hintergrund angewendet, und ein neuerer Schritt bricht die
unfertigen Direktiven eines älteren immer ab.

## Beim Betreten eines Schritts

Nach dem Zurücksetzen wendet Hayali die [Editor-Direktiven](/hayali/handbook/editor-directives) des Schritts in fester
Reihenfolge an: alte Hervorhebungen löschen, Tabs schließen und öffnen, hervorheben, zu einer Zeile springen, dann die
Vorschau.
