# Editor-Direktiven

Ein Schritt kann nicht nur Dateien ändern, sondern auch die Aufmerksamkeit der Lernenden lenken. Der optionale
`editor`-Block und die optionale `preview` beschreiben, was Editor und Vorschau **bei jedem Betreten des Schritts** zeigen
sollen: beim Vorwärtsgehen, beim Zurückgehen und beim Laden der Lektion direkt auf diesem Schritt.

```typescript
{
  id: 'behaviour',
  title: 'Behaviour',
  body: '…',
  editor: {
    close: ['style.css'],
    open: ['index.html', { path: 'app.js', line: 6 }],
    highlight: [{ path: 'app.js', lines: [[6, 9]] }],
  },
  preview: { url: '/about.html' },
}
```

Die Formen sind in [`EditorDirective`](/hayali/api-reference/interfaces/EditorDirective) und
[`LineSpec`](/hayali/api-reference/type-aliases/LineSpec) dokumentiert.

## Keine Vererbung

Direktiven werden allein aus dem Schritt abgeleitet. Ein Schritt ohne `editor` hat keine Direktiven; er wiederholt nicht
die des vorherigen Schritts. Hayali verschiebt nie den DOM-Fokus, und Tabs, die Lernende selbst geöffnet haben, bleiben
offen, sofern der Schritt sie nicht schließt.

## open

Eine Liste von Pfaden, optional als `{ path, line }`. Dateien werden der Reihe nach geöffnet, der **letzte** ist also
aktiv. Hat der letzte Eintrag eine `line`, scrollt der Editor dorthin und setzt den Cursor darauf.

## close

Eine Liste von Pfaden oder `'all'`. Das Schließen läuft vor dem Öffnen, `{ close: 'all', open: ['index.html'] }` lässt
also genau einen Tab übrig. Der Tab einer entfernten Datei wird immer automatisch geschlossen.

## highlight

Eine Liste von `{ path, lines }`. `lines` ist eine **Zeilenangabe** (Line Spec); Zeilen sind 1-basiert und
einschließlich:

| Zeilenangabe | Hebt hervor |
| ------------ | ----------- |
| `3` | Zeile 3 |
| `[3, 7]` | Zeilen 3 bis 7 |
| `[2, [5, 7], 9]` | Zeilen 2, 5 bis 7 und 9 |

Hervorheben öffnet oder fokussiert nie eine Datei. Ist die Datei nicht geöffnet, erscheint die Hervorhebung, sobald sie
geöffnet wird. Alle Hervorhebungen werden gelöscht, wenn Lernende den Schritt verlassen und bei ihrer ersten Änderung,
damit sie nie auf verschobene Zeilen zeigen.

## preview.url

`preview.url` lässt die Vorschau eine Seite zeigen. Sie ist **Root-relativ** (beginnt mit einem einzelnen `/`) und kann
Query und Hash enthalten, zum Beispiel `/about.html?lang=en#top`; die Origin des WebContainers enthält sie nie.

* Beim ersten angezeigten Schritt wartet die URL, bis der Dev-Server bereit ist.
* Ohne `preview.url` bleibt die Vorschau auf ihrer Seite und wird **neu geladen**, damit sie die Dateien des neuen Schritts
  zeigt. Die Ausnahme: Hat ein Schritt Dateien entfernt und steht die Vorschau nicht auf `/`, springt sie stattdessen
  zurück auf `/`. Eine ausdrückliche `preview.url` hat immer Vorrang vor diesem Rückfall (und steht die Vorschau schon auf
  dieser Seite, wird sie neu geladen).

## Wenn eine Direktive falsch ist

Eine Direktive, die außerhalb des Dateibaums des Schritts zeigt, wird in der Entwicklung mit einer Konsolenwarnung
übersprungen; sie wirft nie und bringt die Lektion nicht durcheinander. Nutze
[`validateLesson()`](/hayali/api-reference/functions/validateLesson), um solche Fehler zu finden, bevor es deine
Lernenden tun.

## Auf kleinen Bildschirmen

Ist das Sandbox-Panel hinter dem Lektion/Sandbox-Umschalter verborgen, werden `open`, `close`, `highlight` und `preview`
sofort angewendet. Das Springen zu einer Zeile wartet, bis das Sandbox-Panel sichtbar ist. Hayali wechselt das Panel nie
für die Lernenden.
