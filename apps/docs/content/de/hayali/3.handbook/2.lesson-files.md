# Lektionsdateien

Eine [Lektion](/hayali/handbook/lesson-schema) muss nicht als Objekt geschrieben werden. Sie kann eine einzige
Markdown-Datei sein, eine **Lektionsdatei**, die [`parseLesson()`](/hayali/api-reference/functions/parseLesson) zum
selben `Lesson` kompiliert. Text und Code stehen in echten Fences, und die Lektion lässt sich von oben nach unten lesen.

`parseLesson()` kommt aus `@karagoz/hayali/parse`. Die Funktion ist rein und hat keine Abhängigkeit von Vue oder Node,
sie läuft also im Browser, in einem Build-Skript oder in einem Test. Sie wirft nie eine Ausnahme: Was sich aufbauen
ließ, wird zusammen mit einer Liste von Problemen (Issues) zurückgegeben.

```typescript
import { parseLesson } from '@karagoz/hayali/parse'

const { lesson, issues } = parseLesson(markdown)
```

Eine Lektionsdatei ist in einer Sprache geschrieben. Eine Übersetzung ist eine eigene Datei mit denselben IDs.

## Der Aufbau einer Datei

````markdown
```yaml krgz-lesson
immutable:
  - package.json
```

```json file=package.json
{ "name": "tiny-counter", "private": true }
```

```html file=index.html
<button id="button">Click me</button>
```

```js file=app.js
// Behaviour goes here.
```

# The page {#basics}

## Markup {#markup}

Every page starts as HTML. `index.html` is open in the editor.

```yaml krgz-step
editor:
  open: [index.html]
```

## Behaviour {#behaviour}

`app.js` now handles the click.

```js file=app.js
document.getElementById('button').addEventListener('click', () => alert('Hi'))
```

```yaml krgz-step
editor:
  open: [app.js]
```
````

| Markdown | Wird zu |
| -------- | ------- |
| `# Titel {#id}` | Einem Kapitel. |
| `## Titel {#id}` | Einem Schritt des aktuellen Kapitels. |
| Text unter einer Schritt-Überschrift | Dem `body` des Schritts. |
| Ein Fence mit `file=<pfad>` | Einer Datei: vor dem ersten Kapitel im Basisbaum, in einem Schritt eine Adjustment. |
| Ein `krgz-lesson`-Fence | Lektionsweiten Einstellungen, vor dem ersten Kapitel. |
| Ein `krgz-step`-Fence | Den Direktiven des Schritts, innerhalb des Schritts. |

Nur Überschriften mit `#` und `##` gliedern die Lektion. Tiefere Überschriften gehören zum Text eines Schritts.

## IDs

Jede Kapitel- und Schritt-Überschrift endet auf eine `{#id}`. Eine ID besteht aus Buchstaben, Ziffern, `_` und `-`.
Kapitel-IDs sind in der Lektion eindeutig, Schritt-IDs innerhalb ihres Kapitels. Wie im
[Lektions-Schema](/hayali/handbook/lesson-schema) werden IDs nie aus Titeln abgeleitet. Eine Überschrift ohne ID oder mit
einer ungültigen oder doppelten ID ist ein Fehler. Ein Kapitel ohne Schritte ebenfalls.

## Lektions-Block

Der optionale `krgz-lesson`-Fence enthält lektionsweite Einstellungen. Heute hat er einen Schlüssel, `immutable`, eine
Liste von Mustern für [unveränderliche Dateien](/hayali/handbook/adjustments-and-removals). Erlaubt ist höchstens ein
Lektions-Block, und nur vor der ersten Kapitel-Überschrift.

````markdown
```yaml krgz-lesson
immutable:
  - package.json
  - server.js
```
````

## Datei-Fences

Ein Fence, dessen Info-String `file=<pfad>` enthält, ist eine Datei. Vor dem ersten Kapitel gehört er zum
**Basisbaum**; innerhalb eines Schritts ist er eine der [Adjustments](/hayali/handbook/adjustments-and-removals) des
Schritts. Ein Pfad darf pro Schritt einmal vorkommen und einmal in der Basis. Ein Fence bezieht seinen Inhalt aus
**genau einer** von drei Quellen:

| Geschrieben als | Der Inhalt kommt aus |
| --------------- | -------------------- |
| Einem Rumpf | dem Fence selbst. |
| `from=<ref>` und leerem Rumpf | der Version derselben Datei aus einem anderen Schritt. |
| `src=<pfad>` und leerem Rumpf | einer Datei neben der Lektionsdatei. |

Einen Rumpf zusammen mit `from=` oder `src=` anzugeben, oder `from=` und `src=` zusammen, ist ein Fehler.

### from=

`from=` verwendet eine Datei wieder, statt sie zu kopieren. So behält ein Schritt, was ein früherer Schritt geschrieben
hat:

````markdown
```css file=style.css from=style
```

```js file=app.js from=basics/behaviour
```
````

Eine Referenz ist eine Schritt-ID im selben Kapitel (`style`), ein Schritt in einem beliebigen Kapitel
(`basics/behaviour`) oder `base` für die Version des Basisbaums. Der Schritt muss eine eigene Version dieser Datei haben
oder sie über sein `carry` bekommen; die Basis wird nur herangezogen, wenn du sie angibst. Der Parser löst Referenzen
auf, das kompilierte `Lesson` enthält also keine.

### src=

`src=` lädt den Inhalt aus einer anderen Datei, für Code, der inline zu lang zum Lesen wäre. Der Pfad ist relativ zur
Lektionsdatei und muss in ihrem Ordner bleiben. Das Parsen ist rein, deshalb übergibst du den Leser über die Option
`resolveSrc`; ohne sie ist jedes `src=` unaufgelöst. `srcPaths` im Ergebnis listet auf, was angefordert wurde, und genau
das braucht ein Bundler, um seinen Cache zu invalidieren.

```typescript
const { lesson } = parseLesson(markdown, {
  resolveSrc: (path) => files[path],
})
```

## Schritt-Block

Der optionale `krgz-step`-Fence enthält die Direktiven eines Schritts. Pro Schritt ist höchstens einer erlaubt.

````markdown
```yaml krgz-step
locks: [index.html]
removals: [about.html]
editor:
  close: [style.css]
  open:
    - path: app.js
      line: 6
  highlight:
    - path: style.css
      lines: 1-7, 13-17
preview:
  url: /about.html
```
````

| Schlüssel | Entspricht | Siehe |
| --------- | ---------- | ----- |
| `locks` | `Step.locks` | [Sperren](/hayali/handbook/locks) |
| `removals` | `Step.removals` | [Adjustments und Removals](/hayali/handbook/adjustments-and-removals) |
| `editor` | `Step.editor` | [Editor-Direktiven](/hayali/handbook/editor-directives) |
| `preview` | `Step.preview` | [Editor-Direktiven](/hayali/handbook/editor-directives) |
| `carry` | | [Carry](#carry) weiter unten |

Unbekannte Schlüssel sind Fehler, damit Tippfehler nicht unbemerkt bleiben. Das gilt auch für Fences mit einem anderen
Namen, der mit `krgz-` beginnt.

### Zeilenangaben

In `editor.highlight` akzeptiert `lines` die [Zeilenangabe](/hayali/api-reference/type-aliases/LineSpec) als YAML (`7`,
`[3, 7]`, `[[1, 7], [13, 17]]`) oder als Kurzschreibweise: `7`, `3-7`, `1-7, 13-17`. Zeilen zählen ab 1 und sind
inklusiv.

## Carry

Schritte sind nicht kumulativ: Jeder beginnt bei der Basis und nur mit seinen eigenen Adjustments. Mit `carry` startet
ein Schritt stattdessen von einem anderen:

````markdown
## Behaviour {#behaviour}

```yaml krgz-step
carry: style
```

```js file=app.js
// Only the new file is written. style.css comes from the "style" step.
```
````

Der Schritt bekommt alle Dateien des übernommenen Schritts plus seine eigenen Fences, die gewinnen, wenn beide denselben
Pfad nennen. Die Referenz ist eine Schritt-ID (selbes Kapitel) oder `kapitel/schritt`. Ein übernommener Schritt kann
selbst einen weiteren übernehmen, und die Kette wird verfolgt.

Übernommen werden nur **Adjustments**. Sperren, Editor-Direktiven, die Vorschau und Removals werden nie geerbt, denn sie
beschreiben den Moment eines Schritts, nicht seine Dateien. Entfernt der übernommene Schritt eine Datei, die dieser
Schritt wieder hineinholt, gibt es eine Warnung.

## Issues

`parseLesson()` liefert für jedes Problem ein [`ParseIssue`](/hayali/api-reference/interfaces/ParseIssue), jeweils mit
einer `line` (ab 1), einer `severity` von `error` oder `warning` und einer
[`rule`](/hayali/api-reference/type-aliases/ParseIssueRule), die benennt, was schiefging:

| Bereich | Regeln |
| ------- | ------ |
| Überschriften und IDs | `missing-id`, `invalid-id`, `duplicate-id`, `step-outside-chapter`, `empty-chapter` |
| Fences | `unclosed-fence`, `unknown-fence`, `file-outside-step`, `missing-file-path`, `duplicate-file` |
| Blöcke | `malformed-yaml`, `unknown-key`, `invalid-value`, `misplaced-lesson-block`, `duplicate-lesson-block`, `misplaced-step-block`, `duplicate-step-block` |
| Dateiquellen | `conflicting-file-source`, `ref-with-body`, `src-with-body`, `invalid-src`, `unresolved-src` |
| Referenzen | `ref-unknown-step`, `ref-missing-path`, `ref-cycle` |
| Carry | `carry-unknown-step`, `carry-cycle`, `carry-drops-removals` (die einzige Warnung) |
| Sonstiges | `parser-failure` |

Fehler innerhalb eines `krgz-lesson`- oder `krgz-step`-Blocks zeigen auf den genauen Schlüssel. Das `lesson` im Ergebnis
ist nach bestem Bemühen aufgebaut und deshalb auch bei Fehlern vorhanden; behebe sie, bevor du dich darauf verlässt.

### Parsen und Validieren

Das Parsen prüft die Syntax der Datei. [`validateLesson()`](/hayali/api-reference/functions/validateLesson) prüft die
kompilierte Lektion gegen die aufgelösten Dateien jedes Schritts, zum Beispiel eine Hervorhebung in einer Datei, die der
Schritt nicht hat, oder in einer Zeile hinter ihrem Ende. Beide melden unterschiedliche Probleme, führe also beide aus.
Validierungs-Issues nennen Kapitel, Schritt und Pfad, keine Zeile; mit `locate()` aus dem Ergebnis bringst du sie auf
eine Zeile zurück.

```typescript
import { parseLesson, validateLesson } from '@karagoz/hayali/parse'

const { lesson, issues, locate } = parseLesson(markdown)
for (const issue of issues) console.log(`${issue.line}: ${issue.rule} ${issue.message}`)

if (!issues.some((issue) => issue.severity === 'error')) {
  for (const issue of validateLesson(lesson)) {
    const line = locate({ chapterId: issue.chapterId, stepId: issue.stepId, path: issue.path }) ?? 1
    console.log(`${line}: ${issue.rule} ${issue.message}`)
  }
}
```
