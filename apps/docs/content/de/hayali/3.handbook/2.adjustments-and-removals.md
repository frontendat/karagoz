# Adjustments und Removals

Eine Lektion hat einen **Basisbaum** (`Lesson.files`). Jeder Schritt beschreibt den Dateibaum, den er haben möchte, als
kleine Änderung darauf:

```
Schrittbaum = Basisdateien + Adjustments des Schritts − Removals des Schritts
```

* **Adjustments** (`Step.adjustments`) fügen Dateien hinzu oder ändern sie. Sie haben dieselbe verschachtelte Form wie der
  Basisbaum.
* **Removals** (`Step.removals`) sind Pfade, die beim Betreten des Schritts gelöscht werden.

## Schritte sind nicht kumulativ

Der Baum eines Schritts wird aus der Basis und **nur seinen eigenen** Adjustments aufgebaut. Er erbt nicht die
Adjustments des vorherigen Schritts. Soll Schritt 3 noch das CSS aus Schritt 2 enthalten, führt Schritt 3 es erneut auf:

```typescript
const styled = { 'style.css': file('body { margin: 0 }') }

steps: [
  { id: 'style', title: 'Style', body: '…', adjustments: styled },
  { id: 'behave', title: 'Behave', body: '…', adjustments: { ...styled, 'app.js': file('…') } },
]
```

Dadurch ist jeder Schritt reproduzierbar: Vor- und Zurückgehen führt immer zum selben Zustand.

## Was beim Wechsel passiert

Beim Betreten eines Schritts entfernt Hayali die Dateien des alten Schritts, die nicht im neuen Baum sind, und schreibt
dann den neuen Baum. Deshalb verschwindet eine Datei, die ein Schritt hinzugefügt hat, im nächsten einfach wieder. Sie
unter `removals` aufzuführen ist erlaubt und macht die Absicht deutlich (die Demo tut das mit `about.html`); `removals`
löscht Dateien, die in der **Basis** liegen.

Verschwindet eine Datei auf diese Weise, schließt sich ihr Editor-Tab von selbst. Und wenn die Vorschau auf einer Seite
stehen geblieben ist, die es nicht mehr gibt, springt sie zurück auf `/` (außer der Schritt hat eine eigene
[`preview.url`](/hayali/handbook/editor-directives)).

## Unveränderliche Dateien

Manche Dateien sollten nie angefasst werden, zum Beispiel `package.json` und das Server-Skript. Führe sie in
`Lesson.immutable` auf (Muster im gitignore-Stil). Unveränderliche (immutable) Dateien werden einmal beim Start gemountet
und weder auf Änderungen überwacht noch zurückgesetzt. Alle anderen sind **zurücksetzbare** Dateien.

`node_modules` und die Lockfiles, die Paketmanager schreiben (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`,
`bun.lock`), sind immer unveränderlich, ob du sie aufführst oder nicht. Das Installieren von Abhängigkeiten nach dem Start
zählt also nie als Änderung, und ein Zurücksetzen löscht sie nie.

::hint
Unveränderlich ist nicht dasselbe wie [gesperrt](/hayali/handbook/locks). Unveränderlichkeit betrifft das Zurücksetzen;
eine Sperre macht eine Datei nur für einen Schritt in der Oberfläche schreibgeschützt.
::
